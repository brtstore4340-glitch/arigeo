CORE PATTERNS DOCUMENTED:

  1. LEASE-BASED FAILOVER (Phase 6)
     - TTL: 30 seconds with 5-second heartbeats
     - Checkpoint: Task state preserved on renewal
     - Transfer: Generation increments prevent stale leases
     - Failover: Sub-30-second recovery, zero work loss

  2. BYZANTINE CONSENSUS (Phase 7)
     - Config: 25 Oracles, f=3 tolerance, quorum=13
     - Validation: 3-layer (heartbeat + hash + resources)
     - Isolation: Critical incidents → immediate isolation
     - Correctness: Guaranteed even if 3 Oracles malicious

  3. FEDERATED LEARNING (Phase 10-A)
     - Local training: Each Oracle improves from task feedback
     - Aggregation: Model weights averaged by accuracy metric
     - Versioning: Global model version prevents skew
     - Distribution: New model synced to all 25 Oracles

  4. AUTONOMY BY REPUTATION (Phase 10-A)
     - Authority matrix: Per-action thresholds (0.5-0.9 range)
     - Decision rule: Execute if random() < authority[action]
     - Learning: Good outcomes increase autonomy, bad decrease
     - Incentive: Self-regulation toward optimal authority

NOTABLE DESIGN DECISIONS
================================================================================

1. NO CENTRAL COORDINATOR
   Authority is earned, not granted. Every Oracle can propose, vote, execute.

2. CHECKPOINT-BASED RECOVERY
   Tasks resume from exact state, not from beginning. Zero work loss on failover.

3. APPEND-ONLY LOGS (JSONL)
   All history is immutable. Enables full auditability and replay capability.

4. REPUTATION AS AUTONOMY ENGINE
   Autonomy thresholds per action type, learned over time. Aligns incentives.

5. PATTERN-BASED AUTO-RECOVERY
   System recognizes failure patterns and proposes fixes autonomously.
   Failure becomes a teaching moment, not a blocker.

6. DISTRIBUTED BRAIN (ψ MEMORY)
   No shared database. Coordination via shared memory layer.
   High autonomy + high transparency.
