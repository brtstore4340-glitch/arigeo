Every vitest run in this session required either timing out or waiting 9+ minutes. The config has a comment about WSL2 issues but no documented expected runtime. Running `npx vitest run` without knowing the expected duration is like starting a build without knowing it takes 20 minutes. The friction is that there's no fast signal — no `--smoke` mode, no warm cache. The 3 pre-existing failures also create noise (I had to verify they weren't my fault).

## Lessons Learned

**1. Check git log before reading task files — implementation may be done.**
When arriving on a branch with a pending task contract, run `git log --oneline -5` first. If a commit matching the task description is present, start from verification mode, not implementation mode.

**2. Vitest full-suite on WSL2 requires explicit timeout budget.**
Before running `npx vitest run` on this repo, allocate 10+ minutes. The vitest config has known WSL2 optimizations but the startup cost is still ~8 minutes. Use `tsc --noEmit` as the fast type-check signal and reserve vitest for full-suite validation only.

**3. Git index 0 bytes = run `git read-tree HEAD`, not `git reset --hard`.**
When `git ls-files` returns `fatal: index file smaller than expected`, the correct recovery is `git read-tree HEAD`. This rebuilds from the last commit non-destructively. Do not use `git reset --hard` which would wipe uncommitted working tree changes.
