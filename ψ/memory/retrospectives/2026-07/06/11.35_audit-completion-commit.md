## Lessons Learned

**Pattern**: Completion and documentation are distinct from execution; both are necessary

**Rule**: When a previous session has completed the critical path but deferred optimization, the follow-on work is to:
1. Document what was completed (learning files, retrospectives)
2. Commit the completed work to git
3. Do NOT attempt the deferred optimization in the same workflow

Attempting to fold optimization into the commit step creates scope creep and loses the benefit of the critical-path separation.

**Applies to**: Any multi-phase work where criticality varies (migrations, audits, refactors, deployments)
