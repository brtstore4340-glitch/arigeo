## Lessons Learned

1. **Nested repos need explicit handling** — When a git repository contains multiple subrepositories with their own `.git` directories, aggressive cleanup operations (git clean, rm -rf) will either timeout or hit protected paths. Always enumerate nested repos first with `find . -maxdepth 2 -name .git -type d` before bulk operations.

2. **Symlinks are environment-specific** — A symlink that works on one machine (where the target path exists) will become a "broken symlink" on another (where the target doesn't exist). For portable, multi-environment projects, prefer regular files or use environment-aware symlink resolution.

3. **Ask before destructive operations** — "Untrack X" is ambiguous. It could mean: (a) remove from working tree, (b) add to .gitignore, (c) remove from git index. Always confirm with the user before running `rm -rf` or `git clean -fd`, even if they sound urgent.

4. **Git state recovery: check submodules first** — When `git status` fails with submodule errors, use `--ignore-submodules=all` as a diagnostic step. This helps identify which submodule is broken without blocking status output.
