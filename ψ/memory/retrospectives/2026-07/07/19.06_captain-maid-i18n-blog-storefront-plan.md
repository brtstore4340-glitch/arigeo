## Lessons Learned

- When a deployment build fails with a generic error ("framework not detected," "package.json not found"), always read the build log's stated branch/commit against `git log --all --oneline` for that exact hash before touching config files — config changes are a distraction if the wrong ref is being built in the first place.
- In multi-oracle/multi-agent fleet setups, before investing exploration effort (parallel Explore agents, deep codebase reads) on a freshly-pasted large spec, confirm the task is still assigned to you — check for signs of parallel delegation (other agents, other oracles, prior escalation threads) rather than assuming a pasted spec is a fresh unclaimed task.
- `git clean -fd` is unsafe to run unbounded in a repo containing large vendored/nested directories (other oracles' `node_modules`, build artifacts checked into a memory tree) — scope it with a path or `-n` dry-run first, especially under a command timeout.
- For i18n bugs specifically: `grep -L` (files NOT containing a pattern) combined with a components-that-import-`useTranslations`-but-lack-`t(` heuristic is a fast, reliable way to locate hardcoded-string regressions across a component tree.
