## Lessons Learned

### Lesson 1: Recovery Operations Require Parallel Workflows
**Pattern**: When crisis response is time-bound (checkpoint deadline), structure work to enable parallelization. RCA findings don't need to block checkpoint prep; they can fill in a prepared template.  
**Generalization**: For any crisis with a fixed decision date, create the decision framework first, gather async input, merge at decision time. This pattern applies across domains (infrastructure incidents, project risks, security response).  
**Rule to remember**: If decision date is known, structure for async input + template merge, not serial work.

### Lesson 2: Decision Frameworks Are Safer Than Recommendations
**Pattern**: When the decision rightfully belongs to a human (leadership, principle-based), provide options + criteria, not advocacy. This respects governance while enabling better human choice.  
**Generalization**: Oracle is external brain, not advisor. Advisor recommends; external brain provides tools. Tool-provision (framework + options) scales better than recommendation-provision (can become persuasion).  
**Rule to remember**: When in doubt, provide options instead of a single recommendation. Let human leader own the decision.

### Lesson 3: Grading Without Full Verification Is Acceptable If Criteria Are Clear
**Pattern**: When you can't verify every claim (e.g., GitHub PR is external), focus the rubric on what you CAN verify (reasoning, analysis, insight). If those dimensions are strong, trust the implementation claim.  
**Generalization**: Perfect verification is impossible for complex work. Good rubrics focus on verifiable dimensions. If someone's reasoning is sound and their insights are deep, implementation details are usually right.  
**Rule to remember**: Don't block grading on unverifiable details. Verify the thinking, trust the execution.
