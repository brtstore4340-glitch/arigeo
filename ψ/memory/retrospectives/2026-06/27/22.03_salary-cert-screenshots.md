## Architecture Decisions

**Decision 1: Separate HTML manual from markdown**
- *Why*: Markdown (MANUAL_TH.md) works for GitHub documentation; HTML (manual.html + manual-with-screenshots.html) works for end-user browsers
- *Tradeoff*: Requires maintaining two formats. Benefit: flexibility in distribution

**Decision 2: Playwright instead of manual screenshots**
- *Why*: Automated capture is reproducible, scalable, and can be re-run if UI changes
- *Tradeoff*: Requires Node.js + Playwright install on Windows. Benefit: no manual clicking through 8 screens each time

**Decision 3: Placeholder images with CSS styling**
- *Why*: HTML structure and styling can be complete before actual images. Images are a separate, asynchronous step
- *Tradeoff*: Two-step workflow (create HTML, then run script). Benefit: CSS is validated early, ready for immediate browser viewing after images populate

## Lessons Learned

**Lesson 1: Trust the summary, verify the artifact**

When resuming after context compaction, the summary tells me *what happened*. But I should verify *what exists now* — not by re-reading everything, but by running a quick integrity check (file sizes, timestamps, content hashes). This is faster and more reliable than trusting memory.

*Applies broadly*: Any work with long interruptions, team handoffs, or external context loss.

**Lesson 2: Own constraints immediately**

When asked "Can you do X?" the answer is either "Yes, I'm doing it" or "No, here's the blocker." Not "Maybe, let me try a few approaches." Waffling erodes trust and wastes time. If it's a genuine blocker (can't run Windows tools in Linux), say so confidently.

*Applies broadly*: Responding to user questions, managing expectations, keeping work moving.

**Lesson 3: Distinguish verification from communication**

Verification is internal work (I need to know files are correct). Communication is external output (user needs to know what to do next). These are different things. I can verify quietly (read files, run checksums) and communicate results loudly (✅ all verified, here's the workflow). Don't make the user watch my verification process.

*Applies broadly*: Any handoff-heavy work, async job coordination, status reporting.
