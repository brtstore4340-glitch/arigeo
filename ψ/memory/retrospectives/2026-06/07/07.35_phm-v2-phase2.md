## Honest Feedback

**Three friction points from this session:**

1. **Compacted session kills worktree context**: When a session compacts and the conversation resumes in the same job, any stale worktree path in the context is silently invalid. The system gave no warning — I had to figure it out from three consecutive tool failures. A single `pwd`-first habit would have solved this immediately, but the environment gives no cue to prompt it.

2. **Write tool requires prior Read within same context window**: The Write tool validates that the target file was read *in this context window*, not just historically. After context compaction, all previous reads are gone. This means even files I had read extensively 10 minutes before the compaction are now "unread" from the tool's perspective. The error message says "must read file first" but doesn't say the compaction reset the read-tracking. Confusing.

3. **Branch creation while "in worktree" is ambiguous**: The EnterWorktree tool gave "already in worktree session" — which made it sound like I was successfully isolated. But I wasn't isolated in the deleted worktree; I was just blocked from creating a new one. The distinction between "you're in a worktree" and "the worktree you think you're in no longer exists" was not surfaced. I had to deduce it by trying `pwd` and reading the output carefully.

## Lessons Learned

**1. After any context compaction or session resume: run `pwd` before touching files.**
State that was valid before compaction (worktree path, file read cache, active branches) should be treated as stale. One `pwd` + `git branch` takes 2 seconds and prevents three-wall tool failures.

**2. Gemini's HTTP 400 ≠ AUTH_FAIL — always parse the response body.**
Most providers use 400 for "bad request" generically. Gemini specifically uses it for "invalid model name." Mapping 400→AUTH_FAIL triggers a 1-hour cooldown on a model name typo — far too aggressive. When cooldown semantics differ per provider, handle per-provider.

**3. `redact()` must be extended proactively when adding new providers.**
Every new provider has a distinct key prefix format (Groq: `gsk_`, Google: `AIza`, query param: `?key=`). Write the redact patterns at the same time you write the probe function — never after. Otherwise a single unredacted log line exposes a live credential.
