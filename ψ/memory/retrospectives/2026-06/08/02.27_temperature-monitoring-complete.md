Supabase has three ways to deploy functions: CLI, Management API, or web UI. The docs don't clearly explain which works when, or that CLI doesn't work in containerized/limited environments. ## Lessons Learned

**1. Recognize infrastructure problems early — they scale work**
When a project is 70% feature-complete but blocked on deployment, the deployment becomes a force multiplier. Building the GitHub Action workflow took 30 minutes but saved the user from 4 manual deployments in the future. Infrastructure blockers deserve the same problem-solving rigor as feature work.

**2. GitHub Actions is the deployment tool of choice for Supabase when CLI is unavailable**
Next time facing a Supabase function deployment problem without CLI access: go straight to GitHub Actions + workflow. It's the production-grade path, works in all environments, and integrates cleanly with the code repo. Document this as a decision rule so future agents don't repeat the API exploration.

**3. Real-time dashboards don't need a backend if the REST API is available**
Built the dashboard with client-side Supabase REST API calls (no custom backend). This is perfectly fine for dashboards because: (1) data freshness comes from the client refresh interval, (2) no session state needed, (3) the anon key prevents cross-user access. Defaulting to build-an-API is wrong here.
