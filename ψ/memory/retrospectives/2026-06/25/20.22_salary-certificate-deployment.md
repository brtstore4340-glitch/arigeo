## Honest Feedback

## Lessons Learned

**1. Use what exists before building new**
- Rule: Before creating new, ask "does something already work?"
- Applies to: Feature work with architectural choices

**2. Production changes need explicit approval**
- Rule: Don't estimate approval - wait for unambiguous "yes"
- Applies to: Any main/production branch work

**3. Cannot design UI blindly - ask user to verify**
- Rule: When changing UI, explicitly ask user to verify before merge
- Applies to: All visual/layout changes

**4. Think 2 layers deep before merging**
- Rule: Simulate consequences before committing
- Applies to: All code changes, especially navigation

**5. Cascade failures come from assumptions**
- Rule: Verify assumptions from user, don't guess
- Applies to: When uncertain about anything
