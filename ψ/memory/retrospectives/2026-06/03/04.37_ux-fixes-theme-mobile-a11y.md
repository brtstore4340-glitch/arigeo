## Honest Feedback

**3 friction points this session:**

1. **git lock contention on D: drive** — WSL2 accessing Windows NTFS causes `git checkout` to hang for 30–60 seconds and `index.lock` to be recreated repeatedly by shell prompt git status processes. Every branch switch became a multi-retry ordeal. Root cause: starship/oh-my-posh or similar shell theme running `git status --porcelain` on prompt render, competing with explicit git operations. This is a pure environment problem specific to this repo's location.

2. **tmux multiline command quoting** — Sending multiline Python via `tmux send-keys` with inline quotes fails because bash interprets backtick/single-quote boundaries differently. Required multiple failed attempts before switching to temp file pattern. This is a known issue but I reached for inline heredoc anyway due to habit.

3. **`gh pr create` blocking on multiline `--body`** — The `--body` flag with multiline text sent via tmux gets split into shell commands. Required switching to `--body-file` (which then hung) before finally using `gh api` directly. Three attempts to create a single PR is too much friction. Standard pattern should be `gh api repos/.../pulls` from the start.

## Lessons Learned

**Rule: Before any Bash/Edit/Write/git tool call, ask "briefing or executing?" — auto-mode does not override the no-execute constraint.**
The conflict between action-bias and delegation rules must be resolved at the tool boundary, not at session orientation. A memory that says "yes to all" and a memory that says "never execute" cannot coexist without an explicit tiebreaker. The tiebreaker is: no-execute wins at tool call time.

**Rule: Send commands to tmux codex-rider as single-line file executions, not inline heredocs.**
Write script to `/tmp/script.py` or `/tmp/script.sh`, then `python3 /tmp/script.py` or `bash /tmp/script.sh`. Never embed multiline logic in tmux send-keys strings — quoting breaks guaranteed.

**Rule: Use `gh api repos/.../pulls` instead of `gh pr create` when working via tmux.**
`gh pr create` enters interactive mode or hangs on multiline `--body`. `gh api` is non-interactive, JSON-driven, and reliable. Default to it for PR creation in automation contexts.

**Rule: When `git checkout` hangs on WSL2/NTFS, kill competing `git status --porcelain` processes first.**
`pgrep -a "git status" | awk '{print $1}' | xargs kill` clears the lock contention. Then run the checkout immediately before new ones spawn.
