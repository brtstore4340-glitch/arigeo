## Honest Feedback
1. **Menu-relay via `maw send` is unreliable for number keys** — I sent bare `3` to select option 3 and it registered as option 1; had to recover with a full text instruction. Number-key selection should never be trusted over send-keys.
2. **Self-matching liveness grep** — my `pgrep -af | grep "jobs/66f34b68"` matched its *own* command string, producing a false "live process" and nearly skipping a safe archive. Liveness checks must exclude own PID / read `/proc/PID/cmdline`.
3. **bg-isolation guard vs vault writes** — writing the Hermes handoff to `ψ/outbox` in the main checkout was rejected, forcing an EnterWorktree mid-wrap-up; the worktree `ψ` is a separate dir, not the vault symlink, so retro/handoff files now need reconciliation back to the real vault.

## Lessons Learned
1. Before claiming *which session or pane you are*, run the topology check (`tmux list-clients` + capture the pane) — identity and location are claims to verify, not assume.
2. When relaying a menu choice into another agent's TUI, send a full TEXT instruction naming the option, not a bare digit — number-key selection does not survive send-keys reliably.
3. Any liveness/ownership grep over process command lines will match itself — exclude your own PID and prefer `/proc/<pid>/cmdline` over `pgrep -f <string-containing-target>`.
