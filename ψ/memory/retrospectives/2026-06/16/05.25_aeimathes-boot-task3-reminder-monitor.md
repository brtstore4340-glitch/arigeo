3. **Driving an interactive TUI via send-keys is fiddly.** The double-Enter submit pattern, clearing the box with Ctrl+U, and waiting for "Zesting/Elucidating" states all required careful sequencing and sleeps; one mistimed Enter would have mis-submitted.

## Lessons Learned
- A shell rc that `cd`s on startup (e.g. `.bashrc` with `cd /somewhere`) overrides `tmux new-session -c` and any wake tool's start-dir. To boot an agent in a specific repo, send `cd <repo> && <cmd>` *after* shell init — don't rely on `-c`.
- When asked to "restart"/"rerun" a scheduled job, read it first: time-only triggers with no date guard will re-fire stale, outward-facing messages. Add date guards + a state file before relaunching anything that messages other agents.
- An outbox note addressed `to: X` is just a label, not delivery. To actually reach an agent, write into *their* inbox (or push via `maw hey`). Build relay explicitly; never assume cross-agent auto-sync.
- Spawning an agent with `--dangerously-skip-permissions` is an authority grant — name it out loud before doing it, even under a standing YOLO/auto order.
