## Honest Feedback
1. **maw FleetView TUI driving is fragile** — every relay went through capture→send-keys→verify cycles; the "Press up to edit queued messages" vs idle states are ambiguous from capture alone, and one early reply mis-landed. Several turns spent confirming a message actually registered.
2. **Background-poll false positives** — my watch regexes matched stale scrollback ("needs input:" from old messages) and a persistent "75% weekly" banner, firing completion/quota signals prematurely twice. Had to relaunch polls with tail-only + hard-block-only filters.
3. **Fleet-wide quota opacity** — khun-ram hit 75% weekly + Lens rate-limited mid-task with no forewarning; I only discovered it via the FleetView banner after dispatching heavy work. No way to check remaining quota before assigning.

## Lessons Learned
- **Before asserting data is absent, grep the user's literal example across every file AND nested payloads (JSON-in-CSV).** Absence claims must be proven against the raw bytes, not just the fields you already modeled. The data owner usually knows it's there.
- **When a delegated oracle is rate-limited, do deterministic work yourself.** Data joins + HTML/report generation need no LLM reasoning — running a Python script beats waiting on a throttled agent.
- **Relay one message at a time through FleetView and verify it registered before sending the next** — queued-message UIs silently stack inputs; bare confirmation from capture is unreliable.
- **Poll completion on tail-only output, never full scrollback** — stale prompts/banners higher in the buffer trigger false signals.
