## Honest Feedback
1. Repeated next-env.d.ts stash dance: every `git switch main` needed `git stash push -- next-env.d.ts` (~10 times). Pure friction.
2. Couldn't read Vercel env directly (vercel link not authed), so every env-config bug (ADMIN_EMAILS, Gmail keys) needed a browser-opened diagnostic endpoint round-trip instead of me checking -- slowed debugging several turns.
3. One-PR-per-tiny-change cadence (22 PRs) is correct given the hook, but commit->push->PR->merge->sync loop is ~5 bash calls each and dominated token spend on a token-restricted session.

## Lessons Learned
- Trace where state is WRITTEN before deciding where to clear/read it. A client-side session clear cannot remove server-set cookies; auth fixes must match the layer that created the session.
- Fire-and-forget async dies on serverless. On Vercel/Lambda always await (or use after()/waitUntil) work that must complete after the response -- un-awaited promises are killed when the function freezes.
- Build a diagnostic endpoint instead of guessing at deploy config. A tiny admin/public JSON endpoint turns invisible env state into facts in one round-trip.
- Event handlers in a Server Component crash the page -- onMouseOver/onClick on RSC elements throws at render; use CSS hover or mark the file 'use client'.
