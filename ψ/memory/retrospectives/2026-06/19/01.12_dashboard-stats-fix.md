## Lessons Learned

**"Same code pattern ≠ same solution when execution context differs."**
- Requests page: Client-side React component, fetches data via API, filters client-side
- Dashboard: Server-side Next.js page, executes on server at build/render time
- Both use same *domain logic* (status filtering) but different *technical context*
- Rule: When copying a pattern from one place to another, verify the execution context (server vs. client, sync vs. async, data source) before assuming it will work the same way. "It works elsewhere" is not evidence; "it works elsewhere *for the same reason*" is.

**"Plan Mode is not optional when velocity leads to rework."**
- Fast iteration without understanding = compound failures (each failed fix makes the next fix harder)
- Slowing down to investigate costs time *upfront* but saves it *downstream*
- Debugging by hypothesis is expensive when you're testing 4 hypotheses before the first root-cause investigation
