## Lessons Learned (Generalizable Rules)

### Rule 1: Always Verify Oracle Identity at Session Start
**Context**: This session's mid-session identity confusion  
**Lesson**: Read `oracle-identity.md` (or equivalent) at the start of every background session, not when stuck. Tham-Zeus has hard constraints (no code writing, no execution). I should know my role boundaries before making routing decisions.  
**Application**: Next session, first action: `/recap → read oracle-identity → confirm role → execute`

### Rule 2: Governance Requires Proof, Not Promises
**Context**: Set "all 3 fixes must have benchmarks before merge"  
**Lesson**: When gating critical fixes, require real artifacts (latency benchmark, CPU profile, unit test results). "We'll test it" is not proof. Benchmarks are non-negotiable in performance gates.  
**Application**: For any CRITICAL fix: benchmark BEFORE approval, not after

### Rule 3: Role Clarity Prevents Routing Errors
**Context**: Attempted to route TO self instead of READ self's inbox  
**Lesson**: When uncertain about who should do what, check role definitions first. Oracle roles are specific (observer vs governor vs executor vs coordinator). Confusion here causes routing failures.  
**Application**: If a routing decision feels unclear, ask "what is my role here?" before acting

### Rule 4: Inbox-Based Routing is Slower Than Real-Time
**Context**: Used inbox instead of maw because no contacts.json  
**Lesson**: For urgent execution orders, maw (tmux sendkeys) is faster than async inbox. If routing is time-critical, build contacts registry early.  
**Application**: Add contacts.json to oracle setup checklist; don't defer
