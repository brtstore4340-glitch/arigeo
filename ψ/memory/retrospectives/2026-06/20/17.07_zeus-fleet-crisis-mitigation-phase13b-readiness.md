## Lessons Learned

**Lesson 1: Offline Oracle Pattern Recognition**
Multiple oracles offline (ធาม 8d, Teleos 16d, Stratum unresponsive) in same session suggests infrastructure pattern, not individual failures. When 2+ oracles go dormant in same window, assume infrastructure issue (network, heartbeat, permissions) rather than individual oracle problem. Investigate root cause before delegating tasks to other oracles (avoid cascading failures like "delegate to Stratum when Stratum is also offline").

**Lesson 2: Async Escalation Confirmation Protocol**
When escalating to async channels (inbox files), lack of receipt confirmation creates ambiguous state. Hermes exchange revealed this pattern: response files existed but Zeus hadn't "recognized" them until explicit ACK file was created. Generalizable rule: for async oracle communication, create explicit confirmation artifacts (ACK files) to force recognition. Makes implicit state explicit.

**Lesson 3: Monitoring Loop Exit Criteria**
Monitoring loops designed to inform deadline decisions. Once deadline passes without response, monitoring becomes sunk cost. Generalizable rule: monitoring loops should have explicit exit criteria (deadline passed, threshold met, pattern detected) rather than requiring manual termination. For deadline-driven loops: auto-exit when deadline time >= deadline threshold.

**Lesson 4: Pre-Delegation Health Check**
Before delegating investigation to oracle X, verify oracle X is online. The pattern: Stratum investigation was delegated to Stratum (who was offline), creating cascading failure. Generalizable rule: when delegating work, verify target oracle health (in-maw, recent activity, or confirmed online status). Avoid delegation cascades.

**Lesson 5: Crisis Mitigation Under Pressure Favors Fallback Paths**
When primary path (Teleos) failed, immediately switching to backup (Dheva) was faster than continued investigation. Generalizable rule: under deadline pressure, fallback paths (backup oracles, alternative solutions) are preferable to continued investigation of broken primary path. The principle holds across system design, incident response, and decision-making.
