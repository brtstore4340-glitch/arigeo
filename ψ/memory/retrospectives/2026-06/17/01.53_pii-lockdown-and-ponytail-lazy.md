## Lessons Learned
- **Treat any phone number, full name, or customer-linked identifier as PII by default in shared/vault writes — redact unless the user explicitly designates the channel as private and asks for the real value.** Don't wait for an explicit "this is PII" instruction before applying the standard; apply it preemptively to ANY personal-data-shaped string, including the human collaborator's own numbers, the moment it appears in a file destined for shared/vault/repo state.
- **When a user issues a blanket compliance rule ("never push X"), audit ALL storage layers, not just the one they mentioned** — working repo, parent repo, shared vault, and any worktrees. The leak this session was in the vault, not the repo the user was thinking about.
- **A small adapted skill (here: /lazy from ponytail) is the right output of /learn --deep + "implement"** — don't over-build; port the minimum reusable artifact (one ruleset file) rather than scaffolding a whole new subsystem around borrowed research.
