## Lessons Learned

### Lesson 1: Parallel Documentation Pattern
**Rule**: When multiple teams need different specs, use skeleton docs with (FILL: ...) placeholders rather than writing every detail. Allows teams to unblock in parallel while you monitor.

**Application**: Use this for any multi-team project where specs are interdependent but teams can work independently on their domain.

### Lesson 2: Credential Verification Checklist
**Rule**: Before committing any credential (API key, token, password) to GitHub Secrets, verify its environment label (dev/test/prod) in source file. Don't assume "looks right."

**Application**: Add a one-line check to credential discovery workflows: "Source says this is [dev/test/prod]?" before commit.

### Lesson 3: Federation Monitoring Setup (Khun-Ram Pattern)
**Rule**: When coordinating across multiple agents, always establish bidirectional monitoring (main agent alerts monitor, monitor updates main). Don't assume messages alone create coordination.

**Application**: Next multi-oracle session, confirm monitoring is two-way before declaring coordination "active."

### Lesson 4: Discover Early, Integrate Late
**Rule**: When you discover new projects mid-session, don't create separate docs. Integrate into existing systems (like PROJECT_REGISTRY) to force design reflexivity and avoid downstream duplication.

**Application**: Use discovery moments to test and improve system design, not just catalog things.
