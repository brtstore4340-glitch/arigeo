## Lessons Learned

### Lesson 1: Parallel Skeleton Documentation Enables Teams
**Rule**: When multiple teams need different specs, use skeleton docs with (FILL: ...) placeholders rather than writing every detail. Allows teams to unblock in parallel while specs converge.

**Application**: Use this pattern for any multi-team project where specs are interdependent but teams can work independently.

### Lesson 2: Credential Verification Checklist
**Rule**: Before committing any credential (API key, token, password) to GitHub Secrets, verify its environment label (dev/test/prod) in source file. Don't assume "looks right."

**Application**: Add one-line check to credential discovery workflows: "Source says this is [env]?" before commit.

### Lesson 3: Discovery Moments Are Design Moments
**Rule**: When you discover new projects/systems mid-session, don't create separate docs. Integrate into existing systems (like PROJECT_REGISTRY) to force design reflexivity and avoid downstream duplication.

**Application**: Use discovery moments to test and improve system design, not just catalog things.

### Lesson 4: Multi-Account Complexity Requires Federation
**Rule**: When projects use different Vercel orgs (salary-cert: team_OS8nENECHPCuieeZsEhya9sF, PEMS: team_okNwqr3o8ikdFxEEpcckhPlC), register them separately with full context. Don't assume all projects share one org.

**Application**: Document org/project/account mappings explicitly in PROJECT_REGISTRY.
