## Lessons Learned

1. **Test assertions must match implementation semantics, not assumed behavior** — before writing `expect(x).toBe(y)`, verify which percentile algorithm (nearest-rank vs. interpolation) the code actually uses. A passing test suite hides a wrong expectation until you run it.

2. **Surface options neutrally when user is the decision-maker** — framing option B as "or it's dead code" is pressure, not information. Present tradeoffs, not threats. The user can weigh dead code vs. useful-in-future-dashboard on their own.

3. **Pre-existing modified files should be checked before any "commit everything" operation** — always run `git diff --name-only` against unstaged changes first; bundle by logical unit, not by "everything that's dirty."
