## Lessons Learned

**Generalizable patterns for future Zeus sessions:**

1. **Parallel dispatch pattern** — When waking >2 oracles with different missions, batch the sends via tmux in a single loop to ensure consistent framing. Reduces chance of one oracle missing context due to pane race conditions.

2. **Session ID detection for background jobs** — Background jobs write to `/home/user/.claude/jobs/<JOB_ID>` not `~/.claude/projects/<ENCODED_PWD>`. Add fallback path: `$CLAUDE_JOB_DIR` if set, else project base. Update dig-miner patterns to try both.

3. **Decision-first, documentation-after = drift** — Lock decisions (commit to memory immediately, not retroactively). When reviewing a proposal, draft the approval memo in parallel with review, then file it atomically. Separating the two creates a window where decisions are "in my head" instead of captured.

4. **Tmux send-keys pattern with confirmation** — Always follow `tmux send-keys <msg> Enter` with `tmux send-keys "" Enter`. Single call leaves message stuck at prompt. This is documented in memory but worth repeating: the pattern is load-bearing.

5. **Proactive clarification > assumption** — "go ahead" was unambiguous in context, but in other sessions it might mean "keep monitoring," "scan for blockers," or "prepare for next milestone." Oracles making resource-intensive decisions (waking 3 agents) should confirm scope before firing.
