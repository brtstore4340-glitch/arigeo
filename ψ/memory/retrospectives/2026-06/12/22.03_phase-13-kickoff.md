## Lessons Learned

**1. Clear decision gates reduce ambiguity**
- Session moved fast (80 min from briefing to activation) because decisions were binary or multi-choice, not open-ended.
- Pattern: Frame every major choice as "Option A, Option B, Option C" with clear trade-offs. Don't ask "should we do Phase 13?" — ask "APPROVE with constraints, DEFER, or HOLD?" Decisiveness follows structure.
- Generalizable: Use this for all future phase kickoffs and strategic decisions.

**2. Redundant persistence (memory + real-time announcement) prevents orphaned decisions**
- Recording approval BOTH in memory AND announcing via maw meant the decision was locked twice (two channels, same message).
- Pattern: For critical decisions, always send via two channels if possible (async + sync). Vault file (persistent) + live message (real-time action trigger).
- Generalizable: Apply to all Oracle activations and phase transitions.

**3. Recommendation + transparency = trust**
- When I proposed the 3-phase strategy and explained the rationale (risk reduction, early validation, incremental PRs), user approved immediately.
- Pattern: Lead with principle, not just the choice. "We should split this into 3 phases because <reason>" beats "Here's the plan."
- Generalizable: Always pair recommendations with one-sentence reasoning.

**4. Momentum matters in activation**
- Activating Aeimathes within 5 minutes of approval (vs. scheduling for "later") ensured immediate start.
- Pattern: Don't let activation windows close. If user approves, dispatch immediately. Async handoff can happen later (if needed), but real-time signal should be instant.
- Generalizable: For all phase transitions and Oracle activations, send the kickoff message same turn as approval.
