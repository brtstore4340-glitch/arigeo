## Lessons Learned

**Lesson 1: Detect agent bottlenecks by +1 hour lag, not by pressure signals**

When orchestrating multiple agents with coupled work (Aeimathes→Khun-Ram→Codex-01 chain), use time as your signal, not user pressure. If an agent hasn't advanced in +1 hour (from last status check), that's the bottleneck. Don't wait for "what are we waiting for?" — surface it proactively.

**Applied rule**: At every 1-hour mark in a multi-agent session, run `maw peek all` and check if any agent is stuck in the same state as 1 hour ago. If yes, escalate immediately. Pressure from above doesn't speed up blockers; clarity + resources do.

**Lesson 2: Parallel execution has a coherence cost; account for synchronization overhead**

Three agents running in parallel sound like 3x speedup. In reality, you get ~2.2x because you must:
1. Spend 10-15 min initializing all three in tmux
2. Spend 5-10 min per decision point to poll all three for status
3. Spend 10-15 min at the gate waiting for the slowest agent to finish

Total synchronization cost: ~40-50 min out of an 8-hour session (8-10% overhead). Budget this upfront.

**Applied rule**: For N agents in parallel, add (N-1) × 15 minutes of sync overhead. With 3 agents, budget 30 minutes pure sync. This prevents the feeling of "we should be done by now" when actually you're just waiting for the slowest thread to finish.

**Lesson 3: Overnight context breaks require explicit handoff state, not implicit recovery**

At 22:00, I took a context break. When I resumed at 02:04, I spent 30 minutes rehydrating: tmux attach, maw peek, pane restoration, status reconstruction. This was operational cleanup, not productive work.

**Better approach**: Before the break, write a 5-line state file:
```
## State Checkpoint (2026-06-12 22:00)
- Aeimathes: blocked on CCPE record filtering (70% done)
- Khun-Ram: in progress Challenge 2 (ETA 04:00)
- Codex-01: awaiting Aeimathes baseline before sprint structure lock
- Next: resume with 'maw peek all' + assess Khun-Ram ETA
- Gate: all three must be ready before Hermes sync (05:00 target)
```

This buys back the 30 minutes and reduces restart confusion.
