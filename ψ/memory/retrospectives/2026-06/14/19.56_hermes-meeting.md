## Lessons Learned

1. **Delegate early, check late** (generalizable: coordination pattern). When Aeimathes + Tham agents are spawned as background tasks, don't block waiting for status updates. Start your own work (in this case, writing retro). Agents will notify on completion. This pattern reduces session latency.

2. **Trust git status over directory heuristics** (generalizable: build/file-management). When an agent or tool writes files, don't assume the path based on symbolic names (worktree/aeimathes-hermes-review). Use `git status --short` to discover actual paths. It's always accurate.

3. **Task-picker mode is a pane state, not a blocker** (generalizable: tmux interaction). When a fresh maw wake lands in interactive picker UI, `C-c` + brief clears it to shell-ready. Don't try to send commands through the picker; it will queue confusingly.

4. **Synthesis contingencies are architecture decisions** (context-specific: Hermes). Aeimathes response + Tham synthesis didn't just say "approved"; both surfaced soft blockers (memory/protocol.md v0 Week 1, file-lock protocol, cross-machine sync deferral). These are design constraints, not risk notes — they belong in the charter, not the risk register. Keep this pattern.
