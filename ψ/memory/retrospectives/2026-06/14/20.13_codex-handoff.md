## Lessons Learned

1. **Handoff anxiety is a trust signal** (generalizable: delegation pattern). When delegating, if I feel the urge to over-brief or over-explain, it's a sign I don't fully trust the recipient's autonomy. The antidote: set clear 3-task structure + timeline + escalation path, then step back. Codex-01 can fill in details.

2. **Tmux briefs need a reusable template** (generalizable: async communication). Sending context via tmux (instead of Slack or email) is low-latency but brittle. Create a standard format: `## MISSION`, `## TASKS`, `## REFERENCES`, `## TIMELINE`, `## SUCCESS CRITERIA`. Reuse each time.

3. **Session init + brief delivery should be atomic** (generalizable: onboarding pattern). "Wake oracle → send brief → confirm ready" should ideally complete in <30s. Current flow takes ~5min (wake time + typing + confirmation). For scaling to 5+ parallel oracles, batch the brief send (send all briefs at once, then wait for readiness signals in parallel).
