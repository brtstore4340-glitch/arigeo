DESIGN PRINCIPLES
════════════════════════════════════════════════════════════════════════════

1. Jarvis does not control the computer directly
   → All actions flow through intent parser, risk gate, executor

2. Proof logging is mandatory
   → Every action recorded in JSONL format
   → Audit trail for security and debugging

3. PowerShell-first architecture
   → No external dependencies (except Windows .NET)
   → Works on Windows 10+ with PowerShell 5.0+
   → Single-machine setup with one-run script

4. Local-first, token-saving design
   → Works offline with Windows SAPI
   → No unnecessary API calls
   → External APIs optional (via env vars)

5. Safe by default
   → Mode: "safe" (approvals required)
   → Allowlist enforcement
   → No destructive actions without explicit approval

6. Transparency (Rule 6)
   → No secrets in source code
   → All API keys from environment variables
   → Configuration is readable JSON

ARCHITECTURE REFERENCE
════════════════════════════════════════════════════════════════════════════

User Input (Thai/English text or voice)
          ↓
    Intent Parser (jarvis-core)
    - Recognizes command patterns
    - Extracts parameters
    - Sets confidence score
          ↓
    Risk Gate (jarvis-core)
    - Evaluates risk level (low/medium/high)
    - Checks allowlist
    - Determines approval requirement
          ↓
    Command Router (jarvis-core)
    - Routes to appropriate module
    - Selects handler function
          ↓
    Executor (module-specific)
    - Executes if approved
    - Dry-run mode if needed
    - Returns result
          ↓
    Proof Logger (jarvis-core)
    - Records to JSONL
    - Updates memory
    - Generates audit trail
          ↓
    Response Generator
    - Formats response
    - Speaks via TTS (jarvis-voice)
    - Returns output
